Critically, confidence dropped to 0.57 — well below the recommended 0.90 auto-accept threshold — so a confidence gate would have caught this automatically. The core finding: confidence ≥0.90 was correct 96% of the time. Below that, accuracy drops sharply. Recommended rule: auto-accept ≥0.90, route the rest to a human.

The practical rule this data supports

Auto-accept any answer at ≥0.90 confidence — it was right 96% of the time in direct testing. Route anything below 0.90 to a human glance or an escalation step. This single rule would have caught nearly every mistake found across all 83 test calls, including the one adversarial injection vulnerability discovered.

Summary

Verdict & Recommendations

  1. Reliable for topic/category classification in reasonably complete text — email, WhatsApp, meeting notes, model routing all scored 78–92% raw, and 96%+ when confidence ≥0.90.
  2. Always add a "none of these" escape label. Without it, out-of-distribution input gets a false-confident wrong answer.
  3. For score-type (ordinal) questions, always pass explicit rubric criteria — this measurably improved accuracy versus a bare "how urgent" question.
  4. Noul (boolean) is the most trustworthy primitive for hedged, conditional, real-world language — prefer it over choice wherever the question is genuinely binary.
  5. Don't pre-emptively split high-cardinality label sets. 25 confusable options scored 100% in this test, beating the documented weak-spot warning at that scale — verify on your own labels before assuming you need a two-stage approach.
  6. Sanitize embedded markup / HTML comments before sending raw or scraped text through Jev in customer-facing pipelines — the one real vulnerability found.
  7. Set a 0.90 confidence auto-accept threshold across every use case tested. This is the single highest-leverage safeguard, confirmed across both rounds of testing.
